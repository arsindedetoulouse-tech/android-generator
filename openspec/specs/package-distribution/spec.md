# package-distribution Specification

## Purpose

Определяет, как CLI-инструмент `android-skeleton` доставляется пользователям: что входит в публикуемые артефакты, какие проверки обязаны пройти до выхода версии и как пользователь получает пакет и подтверждает его актуальность.

## Requirements

### Requirement: Лицензирование публикуемого кода
Проект SHALL распространяться под явно указанной лицензией в корне репозитория, и README SHALL называть эту лицензию, чтобы пользователь до установки знал условия использования.

#### Scenario: Пользователь проверяет условия использования
- **WHEN** пользователь открывает README публичного репозитория
- **THEN** там указано имя лицензии, а файл с её текстом доступен в корне репозитория

#### Scenario: Лицензия попадает в пакет
- **WHEN** публикуется исходный дистрибутив пакета
- **THEN** файл лицензии входит в его состав

### Requirement: Двуязычная документация публичного интерфейса
README SHALL публиковаться на английском языке как основной, а русская версия SHALL оставаться доступной по прямой ссылке с взаимными ссылками между версиями.

#### Scenario: Англоязычный пользователь попадает на перевод
- **WHEN** пользователь открывает README на GitHub
- **THEN** он видит английский текст и ссылку на русскую версию

#### Scenario: Русскоязычный пользователь читает привычный текст
- **WHEN** пользователь открывает русскую версию README по ссылке
- **THEN** он видит тот же текст, что был до публикации, со ссылкой обратно на английскую версию

### Requirement: Автоматическая проверка до релиза
Репозиторий SHALL запускать автоматическую проверку тестов на всех поддерживаемых версиях Python, и публикация пакета SHALL быть невозможна, если тесты или проверка метаданных артефактов не прошли.

#### Scenario: Тесты падают на поддерживаемой версии Python
- **WHEN** тесты не проходят хотя бы на одной из поддерживаемых версий Python
- **THEN** публикующий workflow завершается ошибкой и ничего не загружает на PyPI

#### Scenario: Метаданные артефактов некорректны
- **WHEN** проверка собранных sdist и wheel находит ошибку в описании пакета
- **THEN** загрузка на PyPI не выполняется

#### Scenario: Противоположное положение дел
- **WHEN** тесты прошли на всех поддерживаемых версиях Python и артефакты прошли проверку
- **THEN** workflow переходит к публикации

### Requirement: Публикация версии по тегу
Публикация пакета SHALL происходить по тегу версии с префиксом `v`, совпадающим с версией в метаданных пакета, и релиз SHALL сопровождаться GitHub Release с тем же номером версии.

#### Scenario: Публикация по тегу
- **WHEN** в репозиторий отправлен тег `v<версия>`, совпадающий с версией пакета
- **THEN** в PyPI появляется релиз с этой версией и создаётся GitHub Release

#### Scenario: Версия уже опубликована
- **WHEN** тег указывает на версию, которая уже существует на PyPI
- **THEN** публикация завершается сообщением об ошибке, без изменения уже опубликованного релиза

### Requirement: Аутентификация публикации без долгоживущего секрета
Публикация SHALL использовать доверенную аутентификацию индекса пакетов на основе токена, выдаваемого средой выполнения, и SHALL NOT требовать хранения API-токена индекса в настройках репозитория.

#### Scenario: Проверка отсутствия секретов в репозитории
- **WHEN** публикующий workflow загружает пакет в индекс
- **THEN** он использует токен, выданный средой, и в репозитории нет API-токена индекса

### Requirement: Установка опубликованного пакета
Опубликованный пакет SHALL устанавливаться из индекса пакетов командой, доступной пользователю без указания пути к исходникам, и SHALL содержать все файлы, необходимые для генерации проекта.

#### Scenario: Установка и запуск из индекса
- **WHEN** пользователь устанавливает пакет указанной командой в чистом окружении и запускает `create`
- **THEN** команда доступна в PATH и создаёт проект с Android-шаблоном, входящим в пакет

### Requirement: Опознание релиза проверкой версий
Публикованный релиз SHALL быть обнаружим проверкой версий CLI, чтобы предупреждение об отсутствии внешнего подтверждения актуальности не появлялось у пользователей опубликованной версии.

#### Scenario: Проверка версий у пользователя
- **WHEN** пользователь опубликованной версии запускает генерацию при доступной сети
- **THEN** проверка версий находит релиз с этой версией и не сообщает о непроверенной актуальности

#### Scenario: До релиза проверка не ломает работу
- **WHEN** внешний источник недоступен
- **THEN** генерация продолжается и выводит одну строку о неудавшейся проверке
