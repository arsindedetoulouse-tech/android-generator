# Spec Delta

## MODIFIED Requirements

### Requirement: Создание чистого Android-проекта
CLI SHALL создавать модульный Android-проект в текущем пустом каталоге, используя согласованный стек, навигацию Navigation 3 и SDK baseline без AppScanner-специфичных функций и бизнес-правил.

#### Scenario: Создание проекта с валидными параметрами
- **WHEN** пользователь запускает `android-skeleton create` в пустом каталоге с валидными `--package` и `--application-id`
- **THEN** CLI создаёт `app`, `app:navigation`, `build-logic`, version catalog, модуль навигации `:core:navigation`, модуль презентации `:common:presentation`, модуль тестов `:common:testing`, модуль фичи `:feature:home`, API-модуль фичи `:feature:home-api` и design system

#### Scenario: Навигация сгенерированного проекта
- **WHEN** CLI создаёт проект
- **THEN** навигация построена на Navigation 3, а маршруты объявлены как сериализуемые типизированные ключи, а не как строковые константы

#### Scenario: Отсутствие пустых слоёвых модулей
- **WHEN** CLI создаёт проект
- **THEN** в него не включаются модули доменного и data-слоя верхнего уровня, а слои `data` и `domain` размещаются внутри каждого feature-модуля

#### Scenario: Оформление и тема приложения
- **WHEN** CLI создаёт проект
- **THEN** design system предоставляет токены, типографику, палитру и тёмную тему, а манифест задаёт тему, совместимую с Compose и edge-to-edge

#### Scenario: Порядок модулей в конфигурации сборки
- **WHEN** CLI создаёт проект
- **THEN** список подключаемых модулей содержит все `core`-модули раньше feature-модулей, а файл не содержит пустых строк внутри списка

#### Scenario: Каталог назначения не пуст
- **WHEN** пользователь запускает `create` в каталоге с файлами или подкаталогами
- **THEN** CLI сообщает о конфликте и не изменяет каталог

#### Scenario: Имя проекта не задано
- **WHEN** пользователь не передаёт `--name`
- **THEN** root project name и label приложения выводятся из имени текущего каталога

#### Scenario: Валидация package и application ID
- **WHEN** один из обязательных идентификаторов имеет неверный формат
- **THEN** CLI сообщает об ошибке до создания файлов

### Requirement: Добавление feature-модуля
Команда `add-feature` SHALL добавлять рабочий Gradle feature-модуль со слоями `data`, `domain`, `presentation` и отдельным API-модулем только с навигационным контрактом.

#### Scenario: Добавление фичи в поддерживаемый проект
- **WHEN** пользователь запускает `android-skeleton add-feature <name>` с валидным kebab-case slug в проекте с поддерживаемой metadata
- **THEN** CLI создаёт компилируемый feature skeleton, обновляет Gradle и DI-регистрации и предоставляет route contract для интеграции навигации

#### Scenario: Пакет и идентификаторы фичи
- **WHEN** пользователь добавляет фичу с именем `user-profile`
- **THEN** CLI создаёт lowercase Kotlin package `feature.userprofile` и типы с именами в PascalCase

#### Scenario: Навигационный контракт API-модуля
- **WHEN** CLI создаёт API-модуль фичи
- **THEN** API-модуль является Android-модулем, а его маршрут объявлен как сериализуемый типизированный ключ, пригодный для сохранения back stack

#### Scenario: Рабочая цепочка feature-модуля
- **WHEN** CLI добавляет фичу
- **THEN** CLI создаёт реализацию источника данных, реализацию репозитория, use case и интенты во ViewModel, вызывающие use case, регистрирует репозиторий и use case в DI, а состояние отражает загрузку, данные и ошибку

#### Scenario: Вкладка навигации фичи
- **WHEN** CLI добавляет фичу
- **THEN** CLI создаёт вкладку навигации фичи, добавляющую её маршрут в граф приложения, и сообщает готовый фрагмент кода для подключения вкладки

#### Scenario: Имена ресурсов фичи включают её слаг
- **WHEN** CLI создаёт две фичи
- **THEN** строковые ресурсы каждой получают имена с префиксом из её слага, чтобы при слиянии ресурсов одноимённые строки разных фич не перекрывали друг друга

#### Scenario: Зарезервированное имя фичи
- **WHEN** пользователь добавляет фичу с именем `home`
- **THEN** CLI отклоняет запрос с сообщением о том, что это имя зарезервировано под начальный экран приложения, и не изменяет проект

#### Scenario: NavHost остаётся ответственностью приложения
- **WHEN** CLI добавляет фичу
- **THEN** CLI не изменяет исходники приложения и сообщает, что destination требуется зарегистрировать вручную

#### Scenario: Проект не поддерживается
- **WHEN** metadata отсутствует, неизвестна или несовместима с версией шаблона
- **THEN** CLI сообщает, что проект не поддерживается, и не изменяет его

## ADDED Requirements

### Requirement: Начальный экран приложения
CLI SHALL оформлять начальный экран как самостоятельную фичу с собственным маршрутом, вкладкой навигации и ресурсами, а не как содержимое модуля навигации.

#### Scenario: Начальный экран подключён как фича
- **WHEN** CLI создаёт проект
- **THEN** начальный экран объявлен как сериализуемый ключ в API-модуле фичи, отрисовывается вкладкой навигации среди прочих установщиков и не регистрируется вручную в composition root

#### Scenario: Состав начального экрана
- **WHEN** CLI создаёт проект
- **THEN** модуль начального экрана содержит те же слои и ту же цепочку, что и любая другая фича, включая реализацию источника данных, реализацию репозитория, use case, ViewModel и юнит-тесты ViewModel и репозитория

#### Scenario: Граф навигации не содержит app-owned destination
- **WHEN** CLI создаёт проект
- **THEN** модуль навигации отвечает только за сборку графа и не содержит экранов

### Requirement: Оформление начального экрана
CLI SHALL отрисовывать на начальном экране приветствие по центру и SHALL NOT показывать состояние отсутствия данных, пока источник данных не возвращает модель.

#### Scenario: Приветствие по центру экрана
- **WHEN** приложение запущено
- **THEN** начальный экран показывает приветствие по центру экрана

#### Scenario: Первый запуск с заглушкой источника данных
- **WHEN** приложение запущено, а источник данных ещё не заменён и не возвращает модель
- **THEN** начальный экран показывает только приветствие, без сообщения об отсутствии данных

#### Scenario: Данные после замены источника
- **WHEN** источник данных начального экрана возвращает модель
- **THEN** начальный экран показывает приветствие и значение модели под ним

#### Scenario: Ошибка загрузки видна пользователю
- **WHEN** загрузка начального экрана завершается ошибкой
- **THEN** начальный экран показывает приветствие и текст ошибки под ним

### Requirement: Опциональный возврат в экране фичи
CLI SHALL создавать экран фичи с необязательным действием возврата: кнопка возврата SHALL отображаться только когда действие передано.

#### Scenario: Экран без действия возврата
- **WHEN** экран фичи создан без действия возврата
- **THEN** кнопка возврата не отображается

#### Scenario: Экран с действием возврата
- **WHEN** экран фичи создан с действием возврата
- **THEN** кнопка возврата отображается и вызывает переданное действие

#### Scenario: Начальный экран без мёртвой кнопки
- **WHEN** приложение запущено
- **THEN** начальный экран не содержит кнопки возврата, которая не может выполнить переход
