# Proposal

## Why

На рабочей машине установленная копия `android-skeleton` разошлась с репозиторием: в окружении лежит версия `0.2.0` от 8 октября, а в рабочем дереве уже `0.3.0` с шаблоном `1.2.0`. Команда `create` из PATH молча создавала проекты по старому шаблону, и расхождение обнаружилось только при попытке собрать проект. Отдельная проверка есть только на стороне проекта: `add-feature` в проекте чужого шаблона отказывает сообщением `Unsupported project metadata: Unsupported template version: 1.1.0`, которое не объясняет, в чём расхождение и что делать.

Расхождений два, и ловить их нужно разными средствами: CLI отстал от внешнего эталона (новая версия вышла), и CLI не совпадает с шаблоном проекта, в котором он работает.

## What Changes

- `create` до генерации файлов сообщает версию установленного CLI и версию его шаблона, чтобы результат генерации был однозначно привязан к известной версии.
- Добавляется проверка внутренней согласованности пакета: версия шаблона в коде, версия шаблона в манифесте и требуемая версия CLI в карте поддерживаемых версий обязаны совпадать. Расхождение означает дефект сборки пакета и сообщается как предупреждение.
- CLI сверяется с последним релизом на GitHub и с опубликованной версией на PyPI. Обращения к сети ограничены по времени; при недоступности сети проверка не блокирует генерацию, а сообщает, что актуальность подтвердить не удалось.
- Если пакет установлен из рабочего дерева, CLI сверяет версию в метаданных установки с версией в исходниках и предупреждает, когда дерево впереди установленной копии. Для обычной копии пакета такая сверка невозможна и не выполняется.
- Отсутствие опубликованных релизов и незарегистрированный пакет на PyPI сообщаются как факт, а не как расхождение версий: пока пакет нигде не опубликован, сравнивать не с чем.
- `add-feature` получает отказ с объяснением расхождения между версией CLI и версией шаблона проекта вместо безликого сообщения об ошибке metadata; отказ обходится явным флагом `--force`.
- Флаг `--force` появляется у обеих команд и не влияет ни на что, кроме этой проверки.
- Ни одна проверка версии не блокирует генерацию, кроме расхождения с шаблоном проекта: оно означает гарантированно нерабочий результат.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `android-project-generator`: появляется требование о проверке актуальности установленного CLI перед генерацией и уточняется поведение при несовместимой версии шаблона проекта — вместо отказа без объяснения пользователь получает причину и явный способ её обойти.

## Impact

Затрагивается Python-пакет `android_skeleton`: появляется модуль проверки версий с четырьмя независимыми проверками и построением текстов предупреждений; в `cli.py` добавляются вызовы до записи файлов, флаг `--force` и уточнённое сообщение об отказе по версии шаблона; в `pyproject.toml` добавляется адрес репозитория как источник эталона; обновляются `README.md` и тесты.

Изменение не влияет на состав генерируемого проекта и не поднимает версии: состав файлов шаблона не меняется. Сетевые обращения выполняются из стандартной библиотеки, зависимости пакета не появляются. Время генерации без сети увеличивается на величину таймаутов.
