# Proposal

## Why

Проверка сборки (`--verify`) сообщает об отказе как «Gradle verification failed with exit code 1» и выводит наружу стектрейс Gradle. На машине, где Android SDK не настроен, реальная причина — `SDK location not found` — видна только внутри этого стектрейса. Пользователь без Android Studio и без переменной `ANDROID_HOME` оказывается в тупике: он не знает, что делать, хотя достаточно одной строки в `local.properties` или одной переменной окружения. При этом частично настроенная машина (есть `adb` в `PATH`, но нет переменной, которую читает AGP) выглядит как готовая к работе, и о наличии SDK по `PATH` судить нельзя.

## What Changes

- CLI проверяет местоположение Android SDK **до** запуска Gradle: переменные `ANDROID_HOME` и `ANDROID_SDK_ROOT`, затем `sdk.dir` из `local.properties` сгенерированного проекта. Проверяется не только существование каталога, но и признаки SDK, поэтому битая переменная отлавливается до сборки.
- Проверяется наличие платформ, нужных объявленным в сгенерированном соглашениях `compileSdk`, чтобы случай «SDK есть, но платформа не установлена» не доходил до Gradle.
- При ненастроенном SDK и запрошенной проверке сборки Gradle не запускается; вместо стектрейса выводится сообщение с перечнем проверенных источников, найденными на машине кандидатами и способами исправления для zsh, bash, fish и Windows, включая ссылку на command-line tools для случая без Android Studio.
- Без `--verify` CLI печатает короткое предупреждение о ненастроенном SDK сразу после генерации, чтобы отказ не всплыл позже и в другом месте.
- Обе команды получают флаг `--sdk-dir PATH`, записывающий в проект `local.properties` с указанным путём. Запись выполняется только по явному флагу: на машине может быть несколько валидных SDK, и молчаливый выбор привёл бы сборку к не тому.
- Кандидаты для текста сообщения определяются из положения `adb` в `PATH` и из типовых каталогов установки, что покрывает частично настроенную машину без Android Studio.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `android-project-generator`: меняется требование к проверке компилируемости сгенерированного проекта — проверка сборки получает предварительную диагностику окружения, отказ с понятной причиной вместо стектрейса и явный способ указать расположение SDK.

## Impact

Затрагивается Python-пакет `android_skeleton`: появляется модуль `sdk.py` с резолвером расположения SDK, подбором кандидатов, проверкой платформ и построением инструкции; в `cli.py` добавляются флаги `--sdk-dir` в `create` и `add-feature`, предварительная проверка в `_verify_gradle` и предупреждение при генерации без проверки сборки; обновляются `README.md` и тесты.

Изменение не влияет на состав генерируемых файлов: `local.properties` остаётся вне шаблона и создаётся только по запросу. `version` шаблона и CLI не поднимаются — состав проекта не меняется, а поведение проверки сборки описано спецификацией, а не шаблоном.
